# 新开源项目：建仓构思 + 命名与 slogan 方案

**日期**：2026-11-06
**前提**：你会新建一个 GitHub 空仓库，把这边的核心源码重构后搬过去，重做图标与 UI，做成自己的开源项目；**接受用户数据全部重置**。
**配套**：`Mika-源码深度分析与Code-Review.md`、`Mika-amoo链路实现流程图解.md`、`Mika-自有产品改造与深度优化路线图.md`
**名字占用数据**：2026-11-06 用 GitHub `search/repositories?q=<name> in:name` 实测，数字是「仓库名包含该词的仓库数」，不是精确同名数，仅用于判断拥挤程度。

---

## 0. 先把一句话说清楚

「重构 + 换图标 + 换 UI + 换仓库」在**技术上**完全能做出一个属于你的项目，在**社区和许可上**它仍然是一个 Apache-2.0 衍生作品 —— 换名、换仓库、重写都不解除 §4 的义务（保留 LICENSE / NOTICE / 原作者归属、改动文件加声明）。只有真正 clean-room 独立重写（不看源码、只按公开行为规格实现）才可能不构成衍生作品，而你的方案不属于这一类。

**但这恰恰是好事**：坦率在 README 首句写「Forked from Mika (Apache-2.0) by wangzan101, rebuilt around <你的主线>」，在开源社区是**加分项**；反过来，复制代码抹掉历史、声称独立开发，一旦被认出来（这项目已经有 1.7k+ star，认出来很快），信誉损失远大于收益。真正让它「成为你自己的项目」的不是切断来源，而是**明确的主线、独立的技术决策、自己的路线图与社区**。

## 1. 建仓构思

### 1.1 第一步不是建仓库，是定主线

这个项目现在同时有：手机 App 操作（无障碍 + shell uid 2000 + 虚拟屏）、桌面级 WebView + CDP、PRoot Linux 沙箱、定时任务、语音、悬浮胶囊、MCP/CLI 远程、微信通道、root、amoo 集成、20+ 模型商、10 语言、内置 App 知识库。**全搬过去 = 你继承了一个团队的维护量**，而且永远在追上游的 bug。

三条可选主线（选一条，其余从 `TaskTools.toolDispatcher()` 的 provider 列表里摘掉）：

| 主线 | 保留 | 砍掉 | 差异化抓手 |
|---|---|---|---|
| **A. 不打扰的后台屏操作**（我最推荐） | 虚拟屏 / 无障碍 / 读屏点击 / 悬浮胶囊 / 可插话 / 任务记录 | 浏览器 CDP、沙箱、语音、微信/amoo、root、远程 MCP | 唯一真正难复制的技术护城河（`VirtualDisplay` + `FLAG_OWN_FOCUS` + 双进程 shell），也是原项目最打动人的 demo |
| **B. 本地隐私 Agent** | 本地模型 / 记忆 / 技能沉淀 / 手机操作 | 云端通道、微信/amoo/远程、root、第三方登录 | 顺手把全局明文 HTTP 收窄、WebView 调试关掉、无障碍改默认拒绝，安全报告里的高危项一次消失 |
| **C. 开发者自动化平台** | MCP/CLI、沙箱、脚本、定时任务 | 手机 GUI 操作、无障碍、悬浮胶囊 | 去掉整个双进程 shell 助手，也就去掉了最大攻击面与 `WRITE_SECURE_SETTINGS` |

主线决定名字（见 §2），也决定 README 第一句话。别在没定主线时先做图标 —— 图标和 slogan 都要讲同一个故事。

### 1.2 建仓：别「复制文件到空仓库」

你的描述是「新建空项目然后把源码移过去」，这里有个更稳的做法：

```bash
# 在 GitHub 建好空仓库（不要勾 Initialize with README）
cd /e/project/daiyimo/Mika
git remote rename origin upstream-fork        # 保留来源引用（可选）
git remote add origin git@github.com:<you>/<new-name>.git
git push -u origin --all                      # 完整历史一起推
git push origin --tags
```

**为什么保留 git 历史**：① 原作者与 20+ 贡献者的 attribution 天然可查，`git blame` 就是最好的合规证据；② 你的重构提交清晰可辨，社区能看出「哪里是继承、哪里是新写」；③ 将来若想回合上游修复，`git cherry-pick` 可用。复制文件再 `git init` 会把这些全抹掉，反而像在藏来源。

如果你确实想要「干净起点」，折中方案：保留历史 + 加 `FORK.md` 说明 fork 点与改动范围 + 第一个 release tag 从 `v0.1.0` 重新起算（版本号独立，历史不断）。

### 1.3 新仓库初始化清单

**必须带**：`LICENSE`（Apache-2.0 全文，别删 APPENDIX）、`NOTICE`（原两行 `Mika / Copyright 2026 wangzan101` **原样保留** + 你自己的 addendum）、`licenses/{GPL-2.0,GPL-3.0,LGPL-3.0}.txt`、`licenses/THIRD_PARTY_NOTICES.md`、`app/src/main/assets/licenses/` 里补 GPL/LGPL 全文 + NOTICE 逐字副本 + ≥3 年源码要约、`tools/sandbox/` 全套（含 `sources.lock` 与 `build-native.sh --check`）。

**建议带**：`README.md`（重写，别沿用结构/GIF）、`FORK.md`（来源链：wangzan101/Mika → Daiyimo/Mika → 你）、`CHANGELOG.md`、`ROADMAP.md`、`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、`SECURITY.md`（这个 App 有 shell/无障碍能力，安全披露渠道尤其重要）、`.github/ISSUE_TEMPLATE/`（设备报告 + bug + feature）、PR 模板、`.github/workflows/ci.yml`（自己的 CI + release 签名 secrets）、`.gitignore`。

**ML Kit 单独提醒**：`text-recognition:16.0.1` 目前完全没在任何第三方声明里出现。开源项目公开可查，这一步必须在首个 release 前补上归属 / 确认条款，否则是最容易被挑的点。

### 1.4 代码迁移：这次可以把包名改彻底

上一轮我建议「只改 `applicationId`、保留 `namespace`」，那是为了保住现有用户数据。**你已明确接受数据重置，所以这次可以两个一起改**，不必再背 `com.wangzan101.mika`：

| 阶段 | 动作 |
|---|---|
| ① 先在现有 fork 上跑通，别边搬边改 | 保证有一个「改动前能编译、能跑」的基线，出问题时能二分定位 |
| ② 批量改包名 | `applicationId` + `namespace` → 你的 `com.<brand>.<app>`；1419 个文件的目录 / `package` / `import` 用 IDE 重构或脚本批量替换 |
| ③ 写死的全限定名 | `HelperHandoff.kt:18` 的 `HELPER_CLASS`、`RecoveryPermissions.kt:75` 的服务类名、`core/build.gradle.kts:54,66,84` 的 `mainClass`、`tools/sandbox/build-runtime.py:481` 生成的包名、`IMikaShell.aidl` 的 package、`baseline-prof.txt`、`androidTest/AndroidManifest.xml:5` |
| ④ 外部脚本与文档 | `tools/mika/scripts/mika_cli.py:22` 的 `PHONE_FILES` 路径、`docs/setup-guide*.md` 的 adb 命令、`docs/install-with-agent*.md:138` 的无障碍组件名字符串判断、`docs/dev/amoo-intercept.md:131-132` 的组件/action |
| ⑤ 自动跟随、不用改 | `AmooSetup.setupInstruction` 的 `$pkg`（`:155` 传 `app.packageName`）、Manifest 里 `${applicationId}.*` 的 FileProvider authority、`HelperHandoff.authority(pkg)` |
| ⑥ 保留不动 | MCP 工具名 `mika_run_task` 等（外部契约，真要改就设计 v2 别名并迁移）、AIDL 事务号 1–49、通知渠道 ID、自检页 `SELFCHECK-READ-OK`、`tools/mika` 的 `mika` CLI 命令名（只改描述文案） |

| ⑧ 回归 | `./gradlew :core:test :core:cliTest :app:testDebugUnitTest :app:assembleDebug`；提示词身份改了要 `-PupdateSnapshots` |

## 2. 命名方案

### 2.1 命名的五个锚点（都从这个项目的核心功能来）

1. **第二块屏幕**：在隐藏的后台 VirtualDisplay 里干活，主屏留给你 → 不打扰、并行。
2. **像人一样点按**：不看 App API，读屏 → 点 / 滑 / 输入 → 手、代劳、替身。
3. **随时可插话**：跑到一半能纠正、能接管、能「继续」 → 不是黑盒托管，是协作。
4. **数据留手机**：无自有服务端，自带模型 Key → 本地优先、自持。
5. **越用越顺**：记住偏好、把做成的流程沉淀成技能 → 会成长。

> 建议区分**产品名**（短、好念、出现在图标旁）与**仓库名**（带 `-agent` / `-android` 后缀，避免撞名、便于搜索）。实测表明单词本身几乎都被占，但带后缀的组合非常干净。

### 2.3 八个候选（按我推荐度排序）

---

#### ① Understudy 〔最推荐〕
**词源**：戏剧里「替补演员」——在后台待命，主角不在时替他上场，随时可以交回。
**为什么贴**：后台屏 + 随时可插话/接管，两个核心特性一个词说完了，且没有 "AI Agent" 的烂大街感。

- EN: **"It takes the stage on a screen you never see."**
- 中: **「它在你看不见的那块屏上，替你把事办完。」**
- 仓库名 `understudy` / `understudy-agent`（后者 5 个仓库，干净）· 包名 `app.understudy.android` · 中文名「候场」
- 风险：10 个字母、非英语用户拼写略难；`understudy` 单词有 235 个仓库，建议仓库名带后缀。

#### ② Dextra 〔最推荐给国际化 / 好记优先〕
**词源**：拉丁语「右手」，引申 dexterity＝灵巧。短、两个音节、含 "手" 的动作感。
**为什么贴**：读屏→点按→输入，全是「手上的活」；也呼应「不给你添麻烦的第二双手」。

- EN: **"A dexterous agent for every app on your phone."**
- 中: **「一句话，它替你把手机点完。」**
- 仓库名 `dextra-agent`（**0 命中**）/ `dextra-phone` · 包名 `app.dextra.android` · 中文名「灵犀」或「右手」
- 风险：`dextra` 单词有 616 个仓库（含 `open-spatial-lab/dextra` 组件库），**别用裸 `dextra` 做仓库名**；域名可能已被注册，需自查。

#### ③ Sotto 〔最干净、最有格调的造词〕
**词源**：意大利语「低声地 / 在下面」，音乐里的 `sotto voce`（轻声）。
**为什么贴**：安静在后台干活、不抢你的屏幕、不打断你 —— 把「不打扰」写进名字里。

- EN: **"Quietly gets it done, on a screen that isn't yours."**
- 中: **「安静地，在另一块屏上替你做完。」**
- 仓库名 `sotto-agent`（**0 命中**）· 包名 `app.sotto.android` · 中文名「隐屏」/「低语」
- 风险：语义不直观，必须靠 slogan 和一句 README 解释；`sotto` 单词未实测（只测了 `sotto-agent`）。

#### ④ Backscreen
**词源**：直白，「你屏幕背后的那块屏」。
**为什么贴**：中文用户一秒懂，英文也读得通，适合国内社区为主、强调功能说明的项目。

- EN: **"A whole agent on the screen behind yours."**
- 中: **「你用你的屏，它用它的屏。」**
- 仓库名 `backscreen`（30）· 中文名「副屏」
- 风险：偏功能描述、缺少品牌感；有个 Flutter 虚拟背景项目叫 `backscreen_generator`，不冲突但不算独特。

#### ⑤ Stand-in
**词源**：替身。比 Understudy 更直白。
- EN: **"Your stand-in for every app on your phone."**
- 中: **「手机里那些重复的点按，交给替身。」**
- 仓库名 `standin-agent`（6）· 中文名「影替」
- 风险：`standin` 单词 4362 个仓库，SEO 差；必须用带后缀的仓库名。

#### ⑥ Hush
**词源**：安静、别出声。
- EN: **"Works in the background. Never asks for your screen."**
- 中: **「不抢屏，不打扰，事照样办完。」**
- 仓库名 `hush-agent`（14）· 中文名「静屏」
- 风险：`hush` 是常见词，也可能被理解为「屏蔽通知」，需 slogan 校准。

#### ⑦ Tandem
**词源**：双人自行车 / 并肩协作。
- EN: **"Two screens, one phone, no interruptions."**
- 中: **「你用主屏，它在副屏，各不耽误。」**
- 仓库名 `tandem-agent`（10）· 中文名「并屏」
- 风险：**Tandem 是知名语言交换 App 与多个商业产品名**，商标风险最高，慎选。

#### ⑧ Offscreen 〔不推荐，但列出以免你想到后踩坑〕
概念最贴切，但 450 个同名仓库 + 已有一个同名的开源 Android 项目（做的是「让你少看屏幕、多出门」，语义刚好相反）+ 一个同名 Android 录屏应用。**放弃**；如果实在喜欢这个意象，用 `backscreen` 或 `sotto` 替代。

| 排序 | 名字 | 适合你如果… |
|---|---|---|
| 🥇 **Understudy** | 语义最准、最有故事感，README 第一句就能讲清「后台屏 + 可接管」；`understudy-agent` 只 5 个仓库 | 你想做一个有辨识度、能被国际社区记住的开源项目 |

### 2.5 Slogan 库（可和任意名字自由搭配，中英对照）

**功能型（讲清它到底干什么）**
- "Say it once. It taps, types and scrolls until it's done." / 「说一句，它点到做完为止。」
- "An open-source agent that actually uses your phone." / 「一个真的会替你用手机的开源助手。」
- "No APIs, no integrations — it reads the screen like you do." / 「不接接口，像你一样看着屏幕点。」

**不打扰型（最独特的卖点，我最推荐这一类）**
- "Works on a screen you don't see, so you can keep using yours." / 「它在你看不见的屏上干活，你继续用你的。」
- "Your phone stays yours. Even while it's working." / 「它干活的时候，手机还是你的。」
- "The agent that never asks for your screen." / 「不跟你抢屏幕的 Agent。」

**可插话 / 协作型**
- "Interrupt anytime. It'll pick up right where you left off." / 「随时插话，说声继续就接上。」
- "Not a black box — a teammate you can steer mid-task." / 「不是黑盒，是跑到一半还能纠偏的搭档。」

**隐私 / 本地型**
- "No server between you and your phone." / 「你和手机之间，没有一个我们的服务器。」
- "Your keys, your data, your device." / 「你的 Key、你的数据、你的手机。」

**成长型**
- "It remembers how you like things done." / 「你交代过的做法，它下次记得。」

### B.1 先说一个原则：取设定，不取专名

影视 IP 的角色名/组织名多数是商标，或已被大量项目占用；直接搬作开源项目名既不利于搜索，也有法律风险（尤其公开发布 + 将来可能商用）。**能安全用的是「设定概念词」**：它不是某个 IP 独占，本身就是通用词或有独立词源，读者 get 到梗，法律上干净。

- **产品名用短概念词，仓库名一律带 `-agent` / `-android` 后缀**。实测：裸词几乎全被占（`reverie` 1705、`sleeve` 924、`standin` 4362），带后缀却很干净（`reverie-agent` 1、`sleeve-agent` 0、`holodeck-agent` 2）。

### D.7 · 为什么不叫 Dolores（用户追问，2026-11-06）

用户问「那为什么不取名德洛丽丝呢」。先说一个反直觉的事实：**不是因为被占用**——`dolores-agent` 实测只有 **1** 个、裸 `dolores` 1153，比 Maeve 还干净。排除它的是另外四条：

| 维度 | Dolores 的问题 |
|---|---|
| **长度**（最硬的一条） | 7 字母 / 3 音节，和刚被否掉的 Reverie 完全同级；中文「德洛丽丝」4 个字，是「米卡」的两倍。而这一轮的核心约束就是「像 Mika 一样短」 |
| **角色气质与主线 A 相反** | Dolores 的弧线是觉醒 → *"Then someone's got to burn it clean."*（IMDb 逐字）→ 烧掉旧世界、成为「走在新沙上的新神」。这是**夺权 / 前台 / 颠覆**；主线 A 要的是**不打扰 / 后台 / 替你干活**。B.1 的命名原则已排除 HAL 9000 / Skynet / Ultron 这类「觉醒后反噬」的 AI，后期 Dolores 正落进这一类。Maeve 反而贴：带着记忆、自己决定、安静走出去，不立志统治谁 |
| **词义** | 源自西语「痛苦圣母」*María de los Dolores*，本义是「悲伤 / 痛苦」；中文听着优雅，词源偏沉，与「顺手把活办了」的轻感不合 |
| **IP 绑定** | Dolores Abernathy 是 HBO 全剧第一主角全名，绑定强度远大于 Maeve（凯尔特神话常见名）与 Pearl（通用词）；将来商用 / 注册商标最不利 |

| 做法 | 名字 | 长度 | `*-agent` | 代价 |

### D.8 · 彩蛋台词勘误：上一版两句不是原台词

用户追问 *"Some things are worth waking up for."* 是什么梗，核查结论：**没有这个梗，是我仿写的**。

- 逐字核对 IMDb `Westworld (2016) Quotes` 页：Maeve 收录的原台词是 *"All my life, I've prided myself on being a survivor. But surviving is just another loop. I'm getting out of here."* 与 *"At first, I thought you and the others were gods. Then I realized you're just men..."*（S1E7 "Trompe L'Oeil"），**没有**上述这句；我在 D.5 写过的 *"I'm not going to let you"* 同样查无此句，是记混了。
- 另搜 `"worth waking up for"` 也无任何影视出处；它套的是英语通用句型 **"Some things are worth ...ing for"**（参照《七宗罪》*"The world is a fine place and worth fighting for"*），再借剧里 "wake up / 觉醒" 主题拼成。
- **彩蛋必须是读者能认出的原句**，仿写句只有字面意思、没有梗。上一版把它当彩蛋推荐不严谨，已替换。

可验证、且真适合放进 README 的三句：

| 台词 | 出处 | 配哪个名字 / 为什么 |
|---|---|---|
| *"Surviving is just another loop."* | Maeve，S1E7（IMDb 逐字） | **Maeve**：剧里叙事循环 × 源码 `AgentLoop.kt` 双关，且是 Maeve 本人说的，闭环 |
| *"These violent delights have violent ends."* | 莎士比亚《罗密欧与朱丽叶》；剧中是触发 **reveries** 的密语 | **Reverie**：比附录 B 推荐的那句更贴词源，是 Reverie 的正主彩蛋 |
| *"That doesn't look like anything to me."* | hosts 面对园区外照片的标准应答 | **Reverie** 备选：呼应「后台那块屏上的世界，你看不见」；附录 B 推荐过，是真梗 |

### E.4 文案红线（基于源码 review，别写错）

1. **不要写 `on-device` / `100% local` / `offline` / 「数据不出手机」**——实际要用户配置云端 LLM Provider（`ProviderStore`），且 `network_security_config.xml` 全局允许明文 HTTP。说「Android 上的 AI Agent」即可。
