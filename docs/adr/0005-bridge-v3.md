# ADR-0005 · `maeve-bridge` v3: heartbeat, codes, idempotency

**Status:** Proposed · **Date:** 2026-11-06 · **Spec:** §13.8 · [protocol](../spec/bridge-v3.md)

## Context

The v2 file bridge has four protocol defects, confirmed against `AmooBridge.kt:105-180`
and ten real `out/` results (4 done / 5 cancelled / 1 failed):

1. `running` is written once at start; there is no progress heartbeat. A cancelled-heavy
   sample and the "agent gives up at 4 min / app at 6 min" note both point here.
2. On the 15-minute timeout the app writes `status:"running"` with a note — the skill only
   treats `done/failed/cancelled` as terminal, so the caller spins forever.
3. `note` is free text with no structured `code`.
4. The mailbox is plaintext with no source verification.

The file-bridge `id` (a timestamp generated by the caller) and the internal UUID /
MCP `request_id` are also two unrelated ID contracts, so retries create duplicate tasks.

Changing `applicationId` to `com.daiyimo.maeve` makes the v2 skill's hard-coded
`/sdcard/Android/media/com.wangzan101.mika/amoo/` unreachable. There is no compatibility
shim: MCP `mika_*` aliases only help desktop clients.

## Decision

Ship `maeve-bridge` **v3** with a one-time handshake and the wire contract in
`docs/spec/bridge-v3.md`:

- Add `code`, `step`, `updated_at`, `progress_note` to the response; keep all fields always
  present. Terminal states stay `done / failed / cancelled`; timeout = `failed` +
  `code: TIMEOUT`. **No new `timeout` status.**
- Heartbeat every 5 s or on state/step change; caller treats `now - updated_at > 30 s` as
  stale, waits ≤16 min; Maeve terminates at 15 min.
- `requestId = UUIDv5(NAMESPACE_URL, "maeve:amoo:" + id)` for idempotency. JVM's
  `UUID.nameUUIDFromBytes()` is v3/MD5 — implement SHA-1 v5; `RemoteTaskService.isUuid`
  requires no change.
- Recover stale `*.claimed` files on startup with `failed` + `code: INTERRUPTED`.
- Probe `AMOO_PKG` / `ID_INPUT` / `ID_SEND` at runtime; `SKILL_VERSION = 3`; re-inject once
  into a new conversation.

Signing / source authentication for mailbox writes is explicitly **deferred** past
`v0.1.0` and remains a documented risk in `SECURITY.md`.

## Consequences

Both sides must change in lockstep. There is no graceful degradation to v2 — the handshake
is mandatory. That is acceptable because the capability is hidden and configured once.

## Acceptance

- [ ] A ≥6 min task emits heartbeats and finishes without either side abandoning it.
- [ ] Timeout yields `failed/TIMEOUT`; replaying an `id` produces one task only.
- [ ] A kill mid-task leaves `INTERRUPTED` on next launch.
- [ ] No code path reads the old `com.wangzan101.mika` mailbox.
