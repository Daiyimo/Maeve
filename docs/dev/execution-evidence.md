# 执行耗时与点击证据

## 2026-11-12 真机耗时定位

最近一轮手机任务的原生记录总用时为 247,826ms：34 次模型回复累计 95,816ms，模型请求重试等待 720ms，33 次工具操作及读屏累计 103,411ms，操作节奏补足的停留累计 47,248ms，其余约 631ms。该轮没有批量子动作，以上工具时间没有重复累计。耗时主要发生在执行链路，不能用缩短 Flutter 动画解决。

任务使用标准节奏；原生对部分应用的页面停留会额外放慢。Flutter 迁移时遗漏了 `OperatingPace` 的设置入口，现接回「操作确认方式 → 操作节奏」，直接保存到既有 `FeatureFlags`。快速模式取消额外页面停留并一次写入文本，仍等待界面反馈；对外动作的间隔和授权规则独立生效。设置从下一次任务开始生效，不在用户不知情时切换模式。模型响应时间和反复导航仍取决于模型、页面与任务。

对话界面使用原生 `waitingForModel` 区分「等待模型响应」与实际动作进行中。记录核对也显示模型曾把数字 7 的意图发成数字 2 的控件编号；当时给模型的元素表映射正确。修复前的真实 API 多位数计算复验出现反复操作、错误结果及超过测试时限的情况。可选联网设备回归保留严格的真实画面校验，失败时会取消自己发起的任务；常规 CI 不依赖付费服务。

手机点击工具现优先指引按当前界面的准确标签使用 `element`，让原生匹配目标；编号只在刚核对过标签与编号对应关系后使用。数字和符号键盘明确区分标签与控件编号，批量部分执行后不得盲目重做。对应回归把标签 `7` 放在 `@e91`、标签 `2` 放在 `@e7`，验证实际执行选择 `7` 的控件。工具提示词快照同步更新，既有点击与授权路径不变。

执行记录显示每步和累计的已记录模型、工具、工具等待及重试耗时。工具等待包含页面节奏和批量条件等待；复合工具以最外层的时间为准，不把其子动作再加一次。读取一份执行记录时直接读该次概要，避免每秒遍历全部概要文件。

计算器复验还发现：自绘数字已经改变，控件树仍只暴露历史文本；批量的「等待 37 出现」因此等满 8 秒，模型随后重复输入。`UntilWait` 现在只在正向文字条件未满足时，使用有时限的本机 OCR 补充核对，并再次核对窗口归属。受保护或包含秘密输入框的页面不使用该补充；OCR 空结果不能用于证明文字消失。等待保留原来的总时限与用户打断行为。设备回归同时检查最后的真实截图中是否有计算结果，不以模型自述成功作为唯一依据。

## 点击位置

`AndroidScreen` 在分发点击时保存 `PointerCapture`：

- 坐标单击／双击记录手势节奏实际选择的像素落点和屏幕尺寸，包含相对模型目标的微小偏移。
- `ACTION_CLICK` 记录实际接收动作的可点击控件边界，位置在调用前读取。它没有触摸落点，界面只显示范围框。
- 触摸失败、引用过期或执行被拒绝时，不伪造成功点击证据。没有变化的成功触摸仍可有位置证据。
- 操作前画面来自原有手机屏幕端口；受保护画面不保存。取图失败不阻断点击。

`ScreenContext` 把证据置于只记录的 `ToolExecution.record` / `recordFrame`；经过既有执行入口后，`ActionRecorder` 发出 `RunEvent.Pointer`，并给点击前画面分配独立截图编号。它不会增加发给模型的图文。模型单步、批量子动作使用同一条记录链路。

真机回归发现稳定编号转换曾重建工具结果，丢掉点击前画面；看图定位的分支也有相同问题。两处都改为保留完整结果后仅更新内容，回归覆盖真实稳定编号转换路径。

时间线按步号保存所有实际输入证据。Flutter 对点击前截图画准星或控件框，采用 `BoxFit.contain` 的真实图像区域映射坐标，预览留白不参与坐标换算；全屏放大保留标记。点击后的截图单独显示，不能把点标在跳转后的页面上。

旧记录没有真实触摸证据时，最多显示原本保存的 0–999 目标坐标并明确标为目标。无法回溯随机偏移，也不会补画一个看似准确的实际落点。

## 悬浮胶囊

胶囊和展开卡片固定浅色外观，白底、细紫色边线、低阴影；收起状态为 44dp 圆角浮标。空心日食环延续 Flutter 身份，执行时只有局部边缘扰动，另以小型底部信号、件数和结果角标说明状态。需要处理时保留明确文字与状态颜色，保留拖动、双击截屏、长按语音、确认和接管等原生交互。系统减少动效时静止，不在浮层内尝试模糊其他应用的内容。

## 2026-11-13 开关与记录恢复

设置首页和系统授权页共用一个原生悬浮胶囊开关。关闭映射为 `CapsuleMode.Off`，开启映射为 `Always`，通过原有偏好变化流立即生效，重启后保留；与悬浮窗权限分别显示，关闭不取消任务。保存失败保留读取到的原状态并给出提示。

真实执行记录列表直接读取 `RunStore.list()`，可查看尚在磁盘上的历史截图与位置证据，包含未与对话关联的旧中断记录。新的运行在创建日志时把精确 `recordId` 保存到运行账本；恢复中断对话时保留该编号，通知仍按原有任务编号去重。旧的 `interrupted:` 占位编号不再显示为可打开的详细记录链接，也不按目标文本猜测记录。没有结束事件且已无活跃任务的记录明确显示「记录已中断」，不虚构结束时间。

运行账本保存改为同目录原子替换并允许覆盖，修复 Windows 下再次保存时 `renameTo` 失败；旧格式兼容及恢复回归继续覆盖。

## 2026-11-13 修复后复验

用户在设备上完成模型配置后，使用已配置的 `step-3.7-flash` 执行「清空系统计算器并计算 37+58」。真实记录 `20261113-093854-vwxk9g` 成功结束，耗时 69,997ms：10 次模型调用累计 39,018ms、重试等待 230ms、外层工具累计 30,134ms，另外记录工具等待 1,053ms。既有等待字段混合工具内的条件等待与工具前的节奏停留，不能直接与工具用时相加；有等待时不推算步骤合计，总耗时以开始和结束事件为准。这是单轮测量，不代表不同任务的通用提速比例；仍有多次模型调用和重复操作。

设备测试以最终截图中最大的数字文本区域核对结果为 95，避免误读历史计算。该轮保存 14 份点击前画面及真实无障碍控件范围；人工放大查看时，紫色框准确落在清除键上。放大页面的标题显式使用白色，修复全局标题样式在黑色背景上不可读的问题。
