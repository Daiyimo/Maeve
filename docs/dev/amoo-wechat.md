# Amoo 微信连接

入口：设置 → Amoo → 微信连接。微信私聊文字由 Maeve 收件，交给手机上真正的系统 Amoo 聊天界面，再将界面中的最终回复回发微信。聊天不读取 Maeve 模型 API 配置，也不要求配置 Maeve 模型。

## 使用

1. 开启 Maeve 无障碍服务。点击“打开系统 Amoo”可检查真实入口。
2. 获取绑定二维码，用微信扫码确认。已有绑定保留，无需重新扫码。
3. 默认为前台接入：收到文字后会切到 Amoo。处理时应保持该对话可见、手机解锁。
4. 前台接入验证完成后，可打开“后台接入 Amoo”。它需要系统授权中的手机助手，在独立屏幕中运行同一个 Amoo 界面，保持主屏当前页面。手机助手不可用时明确报错，不自动切到前台；用户正在前台使用 Amoo 时也会拒绝抢占。
5. “通过 Maeve 执行任务”只决定能否通过手机任务文件桥调用 Maeve，关闭后仍可聊天。关闭时同时停用旧的聊天截获，原生文件桥认领并拒绝新任务，避免开关重新开启后执行积压任务。已开始任务需在执行记录取消。
6. 需要手机任务时，在 Amoo 页执行一次接入以覆盖安装版本 6 的技能。技能安装不启动问候任务；普通聊天无需安装后台脚本。开启接入会开启执行开关，只聊天可再关闭。
7. “接收微信消息”控制监听。解绑清除本机微信凭据与待处理账本；离开页面只取消本轮二维码等待。

## 真实入口与会话保护

旧版使用 OpenClaw 默认 main agent，虽然没有调用 Maeve 模型，但它是 ClawPhone 上下文，与手机 Amoo 不同。本版删除该脚本并写入停用控制，不再用 CLI 身份代替系统 Amoo。

前后台都使用 `com.stepos.ailauncher/.chat.activity.ChatMainActivity`，通过该机型的输入框、发送按钮和完成操作读取回复。首次绑定遇到已有聊天会新建微信专用对话。后续检查最近的微信轮次；当前是其他对话或有未发送草稿时拒绝覆盖。请保留该专用对话，避免手动切换或输入干扰。Amoo 重启进入空白页时可继续发送，但界面会话上下文可能丢失，不承诺跨系统重启恢复完整上下文。

后台模式使用手机助手创建的独立显示屏与该屏的无障碍窗口。每一轮结束（包括报错、取消）都先尝试将 Amoo 任务保留在主屏后方，再释放显示屏，完成收尾后才回发微信；不在两轮之间长期持有后台屏幕。手动打开系统 Amoo 时也先等待屏幕释放，并明确指定主屏，不改写 Amoo 数据。系统 Amoo 自身可能在失去前台时结束 Activity，不保证原 Activity 或任务编号始终保留；聊天历史仍由 Amoo 管理。该方式依赖 StepOS 的导出 Activity、固定资源 ID 和多屏支持，不是厂商提供的稳定后台 API。

## 投递与恢复

微信 token 由 Android Keystore 加密，保存在应用私有目录。新的消息信箱也在应用私有 `files/wechat-system-amoo/`，只供原生接入组件使用，不向旧沙箱中转器公开消息。仅接受绑定账号的私聊文本，暂不处理图片、语音、群聊。

请求编号由会话与微信消息编号稳定生成，按持久化接收序号处理。认领后改为 `.working`，重启只报告“结果尚未确认”，不自动重放可能已执行的内容。只有微信明确确认送达才确认账本并清理请求与回复；不确定时保留同一投递编号重试。最近 256 条已确认消息用于去重，旧会话不能发给新绑定账号。

收件长轮询和回复投递各自运行。回复检查间隔 150 毫秒，发送失败后间隔 3 秒重试，没有固定 6 秒等待；总耗时仍包含 Amoo 排队、生成和微信网络时间。普通聊天最多等待 2 分钟，开启手机任务时最多等待 15 分钟；超时会说明结果尚未确认，不代表任务已取消。

## 验证

2026-11-13 在 PZ261A 上使用并排安装的 Maeve Dev 验证，保留用户已有扫码绑定与模型配置：

- 前台真实自我介绍为“Amoo，STEPX Neo 设备内置的智能助手”；完整生产投递循环确认微信送达，约 5.2 秒（含测试启动约 7 秒）。
- 后台使用同一系统入口，完整生产投递确认送达，约 12.8 秒（含测试启动约 15 秒）；每 100 毫秒检查主屏任务未切换。
- 两种模式的 Maeve 模型调用数和远程任务数均未增加，不用提示词强制指定助手身份。
- 单元测试覆盖只读完成答复、流式中间态、历史隔离、重复问答、会话与账号隔离、投递失败保留账本；设置测试覆盖入口、执行开关和后台授权条件。

Flutter 全量 217 项、相关 Android JVM 51 项和文档一致性 4 项通过；原生启动、设置与关闭执行检查通过。

这些耗时是测试样本，不是响应时间保证。此前 Windows 上 Android 全量测试有沙箱、进程、符号链接和持久化相关失败，不将该全量运行记为通过。

## 纯接口接入调查

2026-11-13 检查设备的 AgentBus APK 和运行中的本地套接字，确认系统存在 `@agentbus` 接口；客户端代码含会话创建和聊天消息调用。但这不是普通应用可直接使用的公开 HTTP API。

服务端连接流程读取本地套接字的真实 peer UID，通过 PackageManager 核对声明包名；随后检查可信 UID 集合，不符合时返回 `STEPCLAW_AUTH_DENIED`。该集合由与服务自身签名匹配的已安装包发现，无法读取签名时仅保留自身 UID。Maeve 的普通应用签名和 shell 助手不等于这份系统签名，不能仅设置 clientId、包名或复制 SDK 类就获得调用权限。

后续纯接口路线需要核实厂商提供的授权方式、SDK 或可授权的云端接口，以及独立会话、流式回复与真实 Amoo 能力是否一致。目前未验证普通 Maeve 应用可直连，不把旧 OpenClaw main 或修改自我介绍提示词当成同等替代。

入口占用修复的回归检查已验证：单轮真实回复送达前释放后台屏幕，然后从普通系统入口打开 Amoo，可见真实聊天输入框。但连续测试发现，手动打开前台后下一轮后台有时无法取得聊天输入框；该连续使用检查尚未通过，不能将本次修复当成完整后台稳定性验收。未发送的轮次会明确报错，不自动重复发送或抢到前台。
