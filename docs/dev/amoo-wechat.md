# Amoo 微信连接

入口：设置 → Amoo → 微信连接。微信私聊文字先由 Maeve 收件，再转交 Amoo；Amoo 的最终回复通过同一个微信 Bot 发回。微信聊天使用 Amoo 的会话和模型，不读取 Maeve 的模型 API 配置，不要求用户先在 Maeve 添加模型。只有用户明确要求手机操作且执行开关开启时才交给 Maeve。

## 使用

1. 在 Amoo 页点击开始接入，切到 Amoo 聊天，让它覆盖安装版本 5 的接入技能并启动微信中转进程。已有旧版接入也需要执行一次升级。安装不会启动 Maeve 问候任务或消耗 Maeve 模型 API。
2. 返回微信连接页，确认 Amoo 中转显示运行中。获取二维码，用微信扫码确认；同一手机可截图后在扫一扫中从相册识别。
3. 打开该 Bot 的私聊发送文字。微信连接与 Amoo 中转分别显示状态：微信已连接不等于 Amoo 已开始处理消息。
4. “通过 Maeve 执行任务”决定 Amoo 是否可以通过文件桥发起手机任务。关闭后仍能与 Amoo 聊天；关闭时同时停用旧的聊天截获开关，避免并行执行。已开始的任务需要从执行记录取消。
5. “接收微信消息”只控制微信监听；解绑还会删除私有凭据、待处理账本及会话标识。离开页面会取消本轮二维码等待，已绑定的后台连接保留。

开始 Amoo 接入沿用既有行为，会开启手机任务文件桥。需要只聊天时，在接入后关闭执行开关。手机或 Amoo 沙箱重启使中转进程退出后，可点“修复 Amoo 中转”恢复；修复保留微信绑定和原执行开关。页面只认可版本 3 及以上的中转心跳，接入验证还要求新进程编号，不会用旧进程心跳冒充重启成功。

## 链路与依赖

微信凭据继续由 Android Keystore 加密，保存在应用私有目录。共享信箱没有微信 token，仅包含本次用户文字、Amoo 回复、随机会话标识和执行策略。仅接受绑定账号的私聊文本，暂不处理图片、语音、群聊。

由于 Amoo 沙箱与 Android 网络隔离，中转使用现有媒体目录下独立的双向信箱；不要求开放网关端口或复制 Amoo 密钥。应用会在开始接入时将内置脚本导出，Amoo 在自己的 Linux 沙箱运行它：

```text
/sdcard/Android/media/<应用包名>/amoo/wechat/
  wechat_worker.py
  control.json          接收开关、当前会话、是否允许 Maeve 执行
  requests/<sha256>.json 微信入站消息
  requests/<sha256>.working 已认领、不得自动重跑
  replies/<sha256>.json  Amoo 最终回复
  worker.json           中转进程心跳、版本和进程编号（30 秒过期）
  worker-owner/         通过原子创建目录取得的独占权
```

沙箱需提供 Python 3 和可用的 OpenClaw CLI、网关及模型。脚本使用 [OpenClaw agent 命令](https://docs.openclaw.ai/cli/agent) 的会话参数和 JSON 输出；微信使用独立且可续接的会话，不混入手机聊天页的会话。心跳只表明中转进程和 CLI 文件可用，首条真实回复才能验证网关、模型与微信的完整链路。缺少命令或无法安装时，Amoo 应报告失败，页面保留等待接入状态。

关闭执行开关时，原生文件桥仍认领新请求并返回明确失败，不会将请求积压到开关再次打开后执行。每轮微信对话也会带上当前策略；执行派发前再次检查原生开关。

## 投递与恢复

消息编号与随机会话标识生成稳定的请求编号，断线补交复用同一文件，处理顺序使用持久化接收序号而不是散列文件名。最近 256 条已确认消息保留去重记录。只有微信回复明确发送成功才确认入站并清理信箱；网络结果不确定时使用原投递编号重试。

Android 共享媒体目录不支持传统文件锁。中转使用原子创建目录、进程启动时间与随机所有权标识避免多开；不得绕过锁或自行再起另一个监听器。重启时仅停止同一信箱的中转进程及关联 CLI，其他 Amoo 会话和网关不受影响。

进程中断后的已认领消息不会再次调用 Amoo，以免重复执行实际操作；改为回复“结果尚未确认”。这项恢复只在取得独占权后的启动阶段执行，正常轮询不处理别的进程已认领的文件。16 分钟没有最终回复也会给出明确提示，说明任务可能仍在运行。重新绑定使用新会话，旧会话回复不会转给新账号。

## 验证

离线测试覆盖收发契约、账号与会话隔离、关闭执行时的提示、重复请求、投递失败保留账本、中断不重跑，以及设置页入口和布局。脚本测试使用替身 CLI，不发送真实微信消息。

2026-11-13 在 PZ261A 真机使用并排安装的 Maeve Dev 验收：用户完成微信扫码绑定；6 项原生启动、设置和关闭执行检查通过；中转修复升级检查通过。真实 Amoo 对话并向已绑定微信投递回复的检查耗时 6.3 秒，通过用量账本和远程任务记录确认 Maeve 模型调用数、任务数均未增加。检查不会删除或修改用户的模型配置。

Flutter 全量 215 项、相关 Android JVM 44 项、文档一致性 4 项、中转脚本 13 项通过。Android 全量 1,563 项在本机 Windows 执行有 57 项失败，集中在沙箱、进程启动、符号链接和文件持久化；不将该全量运行记为通过。

这版 StepOS 的 CLI 会在打印完整最终 JSON 后继续保留插件事件循环。中转读取完整最终结果后即完成回复，不等待进程退出；随后清理本次调用进程组。诊断已确认使用 Amoo 的 step-router-v1，未将聊天转给 Maeve 模型。
